# Pantry to Table — 網站第一版規格

目標：用自然語言提供手邊食材、數量、人數、忌口、廚具與時間，食材整理後直接選擇廚具與忌口，再列出單道料理候選；勾選後才搭配主食。

## 必須遵守
- 提供嚴格現有食材與允許補買兩種模式。油、鹽、水等不默認存在。
- 食材可使用精確數量或「半顆、半瓶、一盒、有、足夠」等生活化描述；保留描述，不推算容器容量或重量。
- 第二步只提供廚具／熱源與忌口，不重填食材，不設備料或全項核對勾選框。
- 新增微波爐、烤箱、氣炸鍋、鑄鐵鍋；「不拘」解除設備篩選，結果顯示所需設備。忌口「無」與其他選項互斥。
- 依人數換算並合併整餐用量，精確庫存不得超用；描述式庫存可提供候選食譜與精確用量，未明示足夠時標示「份量請對照」，不得宣稱足量或捏造缺量。未提及的油鹽水仍視為沒有。
- 指定設備時兩模式都不得推薦缺設備的食譜；鑄鐵鍋可作平底鍋使用，但仍需要爐火，其他電器不能代替爐火。此次保持 8 道食譜。
- 忌口先排除再排序；未知忌口要停止推薦並請使用者確認。不把辨識能力描述成過敏安全保證。
- 時間含備料、加熱、烹調與盛盤；第一版採保守的逐菜順序，避免鍋具與人力並行衝突。時間為估算。
- 若使用者要求包含採買，需填採買預留分鐘；路線不等於庫存確認，不把單程時間冒充來回總時間。
- 提供原創步驟教學及逐步操作模式。外部影片搜尋連結明確標為搜尋，不能聲稱已核對影片。
- 附近店家要有實際服務回應才顯示名稱、位置、步行時間；庫存一律未確認，除非有庫存來源。
- 手機可操作，繁體中文，鍵盤可用，錯誤與空結果可讀。
- 公開 repo 僅包含程式、原創示範內容、文件與授權；不得提交金鑰或使用者輸入。

## 第一版實作邊界
內建有限食材與原創蔬食/蛋料理目錄，以及明確標示的基本中文辨識。未啟用 AI 時不假裝具備任意自然語言理解。可選的伺服器 AI 接點只負責整理輸入，輸出仍須人為確認與確定性規則檢查。AI 金鑰需管理者另行設定。

採買接點使用管理者設定的 Google Maps 金鑰，透過地理編碼、Places 與 Routes WALK 取得候選店家與步行估算。沒設定金鑰時提供使用者主動開啟的地圖搜尋，不產生假店家。串接程式可測，真實供應商整合必須在有金鑰的環境驗證。

首次發布為可操作 beta，不宣稱已完成通用 AI 食譜搜尋、影片內容核對、即時庫存或食譜專業審核。後續依實際使用回饋擴充食材庫與服務。

## 本次核准的 on-demand 推薦取代預設整餐組合

- Default 原創八道與 iCook 首批搜尋摘要合流為單道候選；不增加 Default 數量。預設不組合菜單。
- 「搭配成套餐」預設不勾；只有勾選後才追加最多兩次主食搜尋，最多兩組有來源證據的搭配。類型由可擴充規則決定，不窮舉。
- 每次一般搜尋最多三次，連同搭配最多五次；搜尋頁去重、限制篩選及多樣性排序在抓 detail 之前完成。只在點開時抓單篇詳細頁，於本站顯示來源作者、材料及步驟。
- 搜尋摘要不是完整用量／設備契約。資料不足必須標示待核對，已知違反 strict／忌口／設備／時間者排除；詳細頁重新核對。未提供資訊保留未知，不自行估量或假設油鹽水。
- 外部食材保留 free-form 名稱，只有精確 alias 對應才填 internalId。未知份數不換算，描述量不冒充精確量。套餐合併來源用量；已知來源份數先正規化。
- Search cache 五分鐘，detail cache 十五分鐘，為有容量限制的暫存；沒有背景更新。Favorite 儲存 normalized snapshot 於 localStorage，獨立於 Default catalog。
- 全部推薦、來源解析、排序、多樣性、搭配、快取及收藏皆 deterministic。基本中文 parser 優先，LLM 僅保留既有 optional 輸入整理；沒有 API key 核心仍可用，不新增付費服務。
- 不做 crawl、分頁、bulk download、embeddings、vector DB、crawler framework、背景同步、收藏後端或無關重構。
